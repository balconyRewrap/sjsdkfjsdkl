# Структура и работа нейронной сети

## Общая идея модели

Разработанная нейронная сеть решает задачу классификации тональности русского текста. На вход она получает обычную строку на русском языке, например отзыв, твит, новость или комментарий, а на выходе выдаёт один из трёх классов:

- `negative` — отрицательная тональность;
- `neutral` — нейтральная тональность;
- `positive` — положительная тональность.

Модель построена не как дообучение готового языкового трансформера, а как самостоятельная нейросетевая архитектура, обучаемая с нуля. Это значит, что словарь, эмбеддинги, веса attention-слоёв и классификационная голова формируются во время обучения на собранном корпусе русскоязычных текстов.

## Предобработка текста

Перед тем как текст попадает в нейронную сеть, он проходит токенизацию. Все символы приводятся к нижнему регистру, после чего строка разбивается на отдельные токены. Токенами считаются слова, числа и отдельные знаки пунктуации.

Например, фраза:

```text
Отличный товар, всё понравилось!
```

после обработки превращается примерно в такую последовательность:

```text
отличный товар , всё понравилось !
```

Для токенизации используется регулярное выражение:

```python
[\wёЁ]+|[^\w\s]
```

Оно позволяет отдельно выделять русские слова, числа и пунктуацию. Такой подход проще, чем морфологический анализ, но хорошо подходит для базовой transformer-модели, потому что сеть сама учится учитывать сочетания токенов и их контекст.

## Собственный словарь

После токенизации на обучающей выборке строится словарь. В него попадают наиболее часто встречающиеся токены. По умолчанию максимальный размер словаря ограничен 80 000 токенов, а токены с частотой ниже заданного порога могут отбрасываться.

В словаре обязательно есть специальные токены:

```text
<pad> — используется для выравнивания длины текстов в батче;
<unk> — используется для неизвестных слов;
<cls> — специальный токен для классификации всего текста.
```

Каждому токену соответствует числовой идентификатор. Например:

```text
<pad> -> 0
<unk> -> 1
<cls> -> 2
```

Остальные слова получают id в зависимости от частоты появления в обучающих данных.

## Кодирование текста

После построения словаря каждый текст переводится в последовательность чисел. В начало каждой последовательности добавляется токен `<cls>`. Он нужен для того, чтобы модель могла собрать общее представление о всём тексте.

Например, текст:

```text
ужасное качество
```

может быть преобразован в последовательность:

```text
[<cls>, ужасное, качество]
```

а затем в id:

```text
[2, 1543, 829]
```

Если слово отсутствует в словаре, оно заменяется на `<unk>`. Также есть ограничение максимальной длины текста. По умолчанию используется `max_length = 192`, то есть слишком длинные тексты обрезаются до 192 токенов с учётом `<cls>`.

## Формирование батчей

Так как тексты имеют разную длину, перед подачей в модель они выравниваются внутри батча. Более короткие последовательности дополняются токеном `<pad>`.

Например:

```text
[2, 1543, 829]
[2, 452, 391, 8120, 19]
```

после padding превращаются в:

```text
[2, 1543, 829, 0, 0]
[2, 452, 391, 8120, 19]
```

Одновременно создаётся `attention_mask`. Она показывает модели, какие позиции являются настоящими токенами, а какие являются padding:

```text
[1, 1, 1, 0, 0]
[1, 1, 1, 1, 1]
```

Это важно, потому что transformer не должен учитывать искусственно добавленные `<pad>` токены при анализе текста.

## Структура нейронной сети

Главный класс модели называется `ScratchTransformerClassifier`. Его структура состоит из нескольких основных блоков:

```text
1. Token Embedding
2. Position Embedding
3. Transformer Encoder
4. LayerNorm
5. Dropout
6. Linear Classifier
```

Если представить модель как поток данных, получится такая схема:

```text
Текст
  ↓
Токенизация
  ↓
Преобразование токенов в id
  ↓
Token Embedding + Position Embedding
  ↓
Transformer Encoder
  ↓
Скрытое состояние токена <cls>
  ↓
LayerNorm
  ↓
Dropout
  ↓
Linear classifier
  ↓
Логиты классов negative / neutral / positive
  ↓
Softmax при инференсе
  ↓
Итоговый класс
```

## Token Embedding

Первый нейросетевой слой — это `nn.Embedding`. Он превращает числовые id токенов в плотные векторы фиксированной размерности.

По умолчанию размерность эмбеддинга равна:

```text
d_model = 256
```

То есть каждый токен представляется не одним числом, а вектором из 256 вещественных чисел. В процессе обучения модель сама настраивает эти векторы так, чтобы близкие по смыслу или по роли токены получали полезные внутренние представления.

Например, слова вроде:

```text
хороший, отличный, понравилось
```

могут начать формировать признаки, связанные с положительной оценкой, а слова:

```text
плохой, ужасный, разочарован
```

с отрицательной.

## Position Embedding

Сам по себе transformer не знает порядок слов. Для него последовательность токенов без позиционной информации выглядела бы как набор слов. Поэтому к токенным эмбеддингам добавляются позиционные эмбеддинги.

Каждой позиции в тексте соответствует отдельный обучаемый вектор:

```text
позиция 0, позиция 1, позиция 2, ...
```

Позиция `0` обычно соответствует `<cls>`, позиция `1` — первому реальному токену текста и так далее.

Итоговое представление токена получается сложением:

```text
token_embedding + position_embedding
```

Это позволяет модели учитывать не только сами слова, но и их расположение в предложении.

## Transformer Encoder

Основная часть модели — это `nn.TransformerEncoder`. Он состоит из нескольких одинаковых encoder-слоёв. По умолчанию используется:

```text
num_layers = 4
nhead = 8
dim_feedforward = 512
dropout = 0.1
activation = gelu
```

Каждый encoder-слой включает два ключевых механизма:

```text
Multi-Head Self-Attention
Feed-Forward Network
```

Self-attention позволяет каждому токену смотреть на другие токены в этом же тексте и определять, какие из них важны для понимания смысла.

Например, в предложении:

```text
Фильм не плохой, а очень даже хороший
```

важно учитывать, что слово `не` относится к `плохой`, а итоговый смысл становится скорее положительным. Простая модель по отдельным словам могла бы увидеть слово `плохой` и ошибочно склониться к отрицательному классу. Transformer же за счёт attention может учитывать связи между словами.

Multi-head attention означает, что таких механизмов внимания несколько. В данной модели используется 8 голов внимания. Каждая голова может учиться замечать разные типы связей:

```text
одна — связь отрицания со словом;
другая — эмоционально окрашенные прилагательные;
третья — усилители вроде "очень", "крайне", "совсем";
четвёртая — общую структуру предложения.
```

После attention-блока данные проходят через feed-forward сеть. Это небольшая полносвязная нейросеть внутри каждого transformer-слоя. Она дополнительно преобразует признаки каждого токена и помогает модели строить более сложные внутренние представления.

## Использование токена `<cls>`

Для классификации используется не среднее по всем словам, а скрытое состояние первого токена `<cls>` после прохождения через transformer encoder.

Идея такая: во время self-attention токен `<cls>` может получать информацию от всех остальных токенов текста. После нескольких transformer-слоёв его вектор становится компактным представлением всего текста.

В коде это соответствует строке:

```python
cls_hidden = self.norm(hidden[:, 0])
```

Здесь `hidden[:, 0]` — это выход transformer для первой позиции, то есть для `<cls>`.

## LayerNorm

После transformer encoder применяется `LayerNorm`. Нормализация стабилизирует значения внутри вектора `<cls>` и делает обучение более устойчивым. Это особенно важно для transformer-архитектур, потому что внутри них много матричных преобразований и attention-операций.

## Dropout

Перед финальной классификацией используется dropout. Он случайно отключает часть признаков во время обучения. Это помогает уменьшить переобучение: модель не должна слишком сильно полагаться на отдельные признаки, а должна использовать более устойчивые закономерности.

По умолчанию:

```text
dropout = 0.1
```

То есть во время обучения примерно 10% признаков могут временно зануляться.

## Финальный классификатор

Последний слой — это линейный классификатор:

```python
nn.Linear(d_model, num_labels)
```

Он принимает вектор размерности 256 и преобразует его в три числа — по одному для каждого класса:

```text
negative
neutral
positive
```

Эти числа называются логитами. Во время обучения они передаются в `CrossEntropyLoss`, которая сравнивает предсказание модели с правильной меткой.

При проверке или использовании модели логиты дополнительно проходят через `softmax`, чтобы получить вероятности классов. Например:

```text
negative = 0.08
neutral  = 0.15
positive = 0.77
```

В этом случае итоговый класс — `positive`.

## Процесс обучения

Во время обучения модель получает батчи текстов и правильных меток. Для каждого батча выполняется следующий цикл:

```text
1. Тексты преобразуются в input_ids и attention_mask.
2. Модель делает предсказание.
3. Считается ошибка CrossEntropyLoss.
4. Выполняется обратное распространение ошибки.
5. Градиенты ограничиваются по норме.
6. AdamW обновляет веса модели.
7. На валидационной выборке считаются accuracy и macro F1.
```

Для оптимизации используется `AdamW`. Это вариант Adam с корректной регуляризацией весов через `weight_decay`. В проекте заданы такие параметры по умолчанию:

```text
learning_rate = 3e-4
weight_decay = 0.01
epochs = 5
batch_size = 64
```

Также используется `clip_grad_norm_` с максимальной нормой `1.0`. Это защищает обучение от слишком больших градиентов, которые могут сделать процесс нестабильным.

## Оценка качества

После каждой эпохи модель проверяется на валидационной части данных. Считаются:

```text
eval_loss
eval_accuracy
eval_macro_f1
```

Главная метрика для выбора лучшей модели — `macro F1`. Она полезна для задачи с несколькими классами, потому что считает качество отдельно по каждому классу, а затем усредняет. Это важно, так как нейтральных примеров меньше, чем положительных и отрицательных.

Если на очередной эпохе `eval_macro_f1` становится лучше предыдущего результата, веса модели сохраняются в файл:

```text
models/scratch-transformer-sentiment/model.pt
```

Отдельно сохраняются:

```text
vocab.json — словарь токенов;
config.json — параметры архитектуры и список классов;
model.pt — веса обученной модели.
```

## Как модель работает при использовании

Когда модель применяется к новому тексту, происходит почти тот же процесс, что и при обучении, но без обновления весов:

```text
1. Загружается config.json.
2. Загружается vocab.json.
3. Создаётся такая же архитектура ScratchTransformerClassifier.
4. В неё загружаются веса model.pt.
5. Новый текст токенизируется.
6. Токены переводятся в id.
7. Модель выдаёт логиты.
8. Softmax превращает логиты в вероятности.
9. Выбирается класс с максимальной вероятностью.
```

Например, для текста:

```text
Отличный товар, всё понравилось
```

модель должна выдать высокий score для `positive`.

Для текста:

```text
Ужасное качество, деньги на ветер
```

ожидается высокий score для `negative`.

А для текста:

```text
Посылка пришла вчера, размер соответствует описанию
```

скорее всего будет выбран `neutral`, так как в предложении нет ярко выраженной эмоциональной оценки.

## Особенность архитектуры

Главная особенность этой нейросети в том, что она достаточно компактная, но при этом использует transformer-механизм внимания. В отличие от простых моделей на мешке слов или TF-IDF, она учитывает порядок токенов и контекст. В отличие от дообучения большой готовой модели, она обучает все внутренние представления самостоятельно на имеющихся русскоязычных датасетах.

То есть модель сама учится:

```text
какие слова чаще связаны с положительной оценкой;
какие слова чаще связаны с отрицательной оценкой;
как учитывать отрицания;
как обрабатывать нейтральные информационные тексты;
как использовать пунктуацию и усилители эмоций;
как отличать эмоциональный отзыв от фактического сообщения.
```

В результате получилась собственная transformer-сеть для анализа тональности русскоязычных текстов, включающая полный цикл: подготовку данных, построение словаря, обучение модели с нуля, валидацию, сохранение артефактов и последующее использование для классификации новых текстов.
